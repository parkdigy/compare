# npm 패키지 코딩 절차

기능 추가·수정이나 공개 타입, 빌드·배포 설정 변경에 적용한다. 먼저 [저장소 지침](../../../AGENTS.md), [프로젝트 구조](../../../docs/agents/project.md), 관련 구현과 테스트를 확인한다.

## 분석과 구현

- `git status --short`로 기존 변경을 확인하고 보존한다. 기대 동작과 기존 타입 추론을 관련 소스·테스트에서 확인한다.
- 공개 API를 변경할 때 `src/index.ts`의 이름 있는 내보내기와 별도로 관리하는 기본 객체, 기존 별칭을 함께 살핀다. 타입 전용 내보내기는 `export type`을 사용한다.
- 빈 값·null·undefined 조건부 함수는 런타임 값과 반환 타입이 모두 중요하다. 타입 가드와 조건부 타입 변경은 연관 함수에 미치는 영향을 확인한다.
- 비교 및 형식 검사는 실제 구현의 허용 범위를 기준으로 한다. API 변경에 관련된 정상 입력과 경계값, 필요한 타입 추론을 테스트하고 README와 예제를 적절히 갱신한다.
- `dist/`는 Git 추적 중인 생성물이다. 직접 편집하지 않으며 빌드가 기존 변경을 덮어쓰지 않도록 확인한다.

## 검증과 인계

`AGENTS.md`의 타입·lint·테스트 명령을 실행하고, 빌드나 공개 진입점을 변경하면 번들도 확인한다. 배포 설정 변경 시 패키지 파일 목록과 설치 소비자의 모듈 로딩·타입 해석을 확인한다. Watchman 접근 오류 시 별도 테스트와 Rollup 실행은 대체 검증으로 기록하고 표준 빌드 성공과 구분한다.

실패 원인을 코드, 기존 결함, 환경 오류로 구분하고 검사 설정을 완화해 실패를 숨기지 않는다. diff에서 공개 API 누락과 기존 변경 훼손을 확인하고 변경 내용, 검증 결과, 미확인 사항을 한글로 보고한다.

여러 세션에 걸치거나 인계가 필요한 작업은 선택적으로 [작업 기록 양식](templates/task.md)을 `_workspace/<작업명>/task.md`에 복사한다. 기존 기록을 덮어쓰지 않고, 이어받을 때 작업 트리부터 다시 확인한다.
